Yes. **That should be treated as a core rendering rule of the CELL system, not decoration.**

What you have now makes the intended architecture much clearer:

* **CELL tab → opens a visual scene.** The cell image you just provided is the initial/base environment.
* **Housing upgrades replace the base image.** So purchasing the condominium doesn't merely change a stat from `cell` → `condominium`; the displayed environment literally changes to the condominium artwork.
* **Monoliths are a separate persistent overlay layer.** They should be transparent PNGs positioned over the environment at fixed coordinates. Changing the underlying residence does **not** remove them.
* The same principle should apply to other persistent visual objects we add later: they belong to the scene's overlay/state system rather than being baked into the background.
* Therefore the renderer is effectively:

```text
CELL VIEW

┌─────────────────────────────────────────┐
│                                         │
│       CURRENT RESIDENCE BACKGROUND      │
│       jail cell / condo / mansion /     │
│       spaceship / cosmic insanity...    │
│                                         │
│    [Monolith A]       [Monolith B]      │
│                                         │
│          [other persistent objects]     │
│                                         │
└─────────────────────────────────────────┘
```

And technically I'd keep the state separated something like:

```js
cellVisualState = {
    residence: "jail_cell",

    overlays: {
        monolith1: false,
        monolith2: false,
        monolith3: false
    }
};
```

Then rendering is conceptually:

```js
background.src = RESIDENCE_IMAGES[cellVisualState.residence];

renderOverlays(cellVisualState.overlays);
```

So when the player buys the condominium:

```js
cellVisualState.residence = "condominium";
```

the renderer changes **only the bottom/background layer**:

```text
BEFORE

Monolith PNGs
─────────────
Jail Cell PNG


AFTER BUYING CONDO

Monolith PNGs     ← SAME AS BEFORE
─────────────
Condominium PNG   ← REPLACED
```

That's substantially better than treating upgrades as menu entries. **The CELL becomes a visual record of Sally's progression.** You can look at it and immediately see what has happened to her situation.

And this matters enormously once the escalation gets ridiculous. The starting image is this miserable, virtually empty stone prison. Eventually we can replace the entire environment underneath the persistent objects while retaining whatever artifacts she has accumulated. That means the visual transformation itself communicates the progression from **prisoner in a dungeon → absurdly upgraded Sally**.

So yes: **I would put this first on the implementation agenda.** Before adding more CELL purchases, establish the visual renderer correctly so every subsequent housing/monolith/environment upgrade plugs into it rather than requiring us to retrofit the architecture afterward.
